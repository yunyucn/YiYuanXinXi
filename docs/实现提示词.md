# 核心业务逻辑（本系统的灵魂，必须真实实现，不能只做 CRUD）

## 1. 入库管理
- 表单录入血液制品信息，储血号自动生成（前缀+日期+序号）
- 有效期 = 采血日期 + 品种保质期（从 blood_product_dict 读取：全血/红细胞 35 天，血浆 1 年，血小板 5 天）
- 入库前必须录入复检结果；复检不合格不允许入库（直接生成待审批报废记录）
- 必须选择存放冰箱（从 fridge 表选）
- 支持批量入库（一次录多袋，献血者编号可相同）
- 按储血号/献血者/日期查询，入库流水可按时间倒序

## 2. 配血管理（重点）
- 医生端提交输血申请单（患者血型从患者档案带出，可手动改并留痕）
- 技师端收到"待配血"申请，进入配血工作台
- 系统自动推荐可配血袋：按申请品种 + 血型 + Rh + 数量 + 有效期最近优先（FEFO）筛选 status=在库 的血袋
- **ABO/Rh 相容性自动校验（必须写成独立函数 check_compatibility(recipient, donor, product_type)，规则如下）**
  - 红细胞类（全血/悬浮红细胞/洗涤红细胞）：
    - 受者 A 可接受 A、O
    - 受者 B 可接受 B、O
    - 受者 AB 可接受 A、B、AB、O
    - 受者 O 只能接受 O
    - 口诀："供者红细胞抗原不能被受者抗体攻击"
  - 血浆类（血浆/冷沉淀）规则与红细胞相反：
    - 受者 A 可接受 A、AB
    - 受者 B 可接受 B、AB
    - 受者 AB 只能接受 AB
    - 受者 O 可接受 A、B、AB、O
  - 血小板：ABO 同型优先，不同型允许但需提示（视为"相容但警告"）
  - Rh：Rh 阴性受者只能接受 Rh 阴性血；Rh 阳性受者接受 Rh 阴性血允许但提示
  - 返回结构：{ compatible: bool, level: 'ok'|'warn'|'fail', reason: str }
  - 前端根据 level 渲染横幅：ok=绿色、warn=黄色但可提交、fail=红色且提交按钮 disabled
  - 后端提交时二次校验，fail 直接 400 拦截
- 配血结果录入（主侧/次侧/方法/结论），相容则：
  - 血袋状态 → 备血锁定（防止他人选用）
  - 申请单状态 → 已备血
- 配血不相容：血袋保持 在库，记录 cross_match（判定=不相容），申请单状态回到 待配血
- 支持取消配血（解锁血袋，申请单回 待配血，保留历史记录）

## 3. 发血管理
- 发血前核对（后端必须逐条校验）：
  1. 申请单状态 = 已备血
  2. 血袋状态 = 备血锁定 且 属于该申请单
  3. 血袋未过期、未报废
  4. 配血记录存在且判定=相容
- 发血成功：血袋 → 已发血，申请单 → 已发血，生成 issue_record，输血执行状态 = 待执行
- 护士领血核对后确认执行 → 输血执行状态 → 已完成，申请单 → 已完成
- 生成《输血记录单》打印视图（含患者、血袋、配血结果、发血人、核对项、签字栏）
- 支持按储血号打印袋签（二维码用纯前端 qrcode 或 SVG 生成，不联网）

## 4. 输血不良反应（闭环最后一环）
- 护士在发血记录详情中，输血执行完成后可"上报不良反应"
- 表单：反应类型（发热/过敏/溶血/其他）、程度（轻/中/重）、发生时间、处理措施、是否上报血站、备注
- 提交后：血袋详情显示"曾发生不良反应"标记；发血记录显示不良反应摘要
- 不良反应列表页：按患者住院号/血袋储血号/类型/程度/时间筛选
- 同一次输血允许多条不良反应记录

## 5. 输血全周期追溯
- 独立页面，顶部输入住院号
- 后端聚合接口 GET /api/trace/{admission_no}，返回该患者所有输血相关事件
- 前端用 el-timeline 按时间正序展示：
  1. 申请单创建（申请人、时间、品种、量、紧急程度）
  2. 配血记录（技师、方法、主侧/次侧、判定；不相容的也要显示并标红）
  3. 发血记录（发血人、领血护士、时间、血袋列表）
  4. 输血执行确认（确认时间、执行护士）
  5. 不良反应（类型、程度、处理措施）
- 每个节点可点击展开详情；不相容配血节点红色、不良反应节点橙色
- 顶部摘要：该患者累计申请次数、输血袋数、不良反应次数

## 6. 报废管理
- 报废申请 → 科室主任审批 → 生效
- 报废后血袋状态 → 已报废，不可再配血/发血
- 已过期血袋由预警系统自动置为 已过期，可一键批量提交报废

## 7. 自动预警（重点，"自动"必须真实现且可演示，不能前端 if 判断）
### 后端实现
- APScheduler BackgroundScheduler，每 10 分钟扫描一次
- **应用启动时立即执行一次（next_run_time=datetime.now()）**，保证打开系统即有预警
- 提供 POST /api/alerts/refresh 手动触发，返回 { new_alerts, expired_bags, scanned_at, cost_ms }
- 每次扫描写入 scan_log 表

### 预警规则
- 临期：距到期 ≤7 天 → 提示；≤3 天 → 警告
- 过期：已过有效期 → 严重，并**自动把血袋状态改为 已过期**（返回 expired_bags 计数）
- 低库存：某品种+血型 在库数量 < 安全阈值（字典可配，默认红细胞 4U、血浆 800ml）→ 警告
- 待配血超时：申请单提交超 30 分钟仍未配血 → 警告
- 复检未完成：入库超 24 小时仍未录完整复检结果 → 提示
- 去重：同对象同类型且 is_handled=0 的不重复生成

### 演示可见性设计（关键）
- 预警中心顶部显示："上次扫描 14:32:05 ｜ 下次扫描 14:42:05 ｜ 定时任务每 10 分钟"，从 scan_log 读取
- "立即扫描"按钮：点击 → loading → 后端执行 → toast "扫描完成，新增 X 条预警，Y 袋血已自动标记过期，耗时 Z ms"
- 扫描后铃铛红点数字弹跳更新（scale 1→1.2→1，200ms）
- 预警中心列表每条显示：级别色条 + 图标 + 类型标签 + 内容 + 关联对象链接（点击跳血袋详情/申请单详情）+ 生成时间 + 操作（标记处理）
- 标记处理弹窗：处理备注 + 确认 → 状态变已处理，铃铛红点数字 -1
- 库存列表临期行效期列红色脉冲，过期行灰化 + 删除线
- 首页预警卡片：按级别排序显示最新 5 条未处理预警

### 铃铛规则
- 红点数字 = is_handled=0 且 level in (警告, 严重) 的数量
- 提示级不计入红点
- 点击铃铛 → 下拉最新 5 条 → "查看全部"跳预警中心

## 8. 查询与统计
- 入出库查询（时间/品种/血型/操作人）、科室用血统计、报废率统计、不良反应统计
- 日报/月报：入库量、出库量、报废量、期末库存，支持导出 CSV
- 图表：近 7 日出入库趋势折线图、血型库存占比环形图、科室用血柱状图、不良反应类型分布饼图

# 状态机（前后端必须一致，非法流转后端拦截）
血袋：
  在库 →(配血锁定)→ 备血锁定 →(发血)→ 已发血
  备血锁定 →(取消配血)→ 在库
  在库 / 备血锁定 →(报废审批通过)→ 已报废
  在库 →(过期扫描)→ 已过期
申请单：
  待配血 →(开始配血)→ 配血中 →(配血成功)→ 已备血 →(发血)→ 已发血 →(护士确认执行)→ 已完成
  待配血 / 配血中 →(取消)→ 已取消
发血记录：
  待执行 →(护士确认)→ 已完成

# 布局与适配规范（仅 PC 桌面端，不做响应式）

## 适配目标
- 只针对 PC 桌面浏览器（Chrome / Edge 现代版本）
- 设计基准分辨率 1440×900，最小可接受 1280×720，最大适配 1920×1080 及以上
- 不做移动端、平板适配，不写 @media 响应式断点（打印样式除外）
- 不使用移动端组件、手势、触摸事件、下拉刷新等
- 鼠标键盘交互为主；不使用 Element Plus 的移动端样式

## 主框架布局
- 经典后台三区：顶部 Header（64px）+ 左侧 Sidebar（展开 220px / 折叠 64px）+ 主内容区
- Header：左侧 logo + 系统名，右侧面包屑、铃铛、用户头像下拉、暗色切换
- Sidebar：可折叠（本地持久化折叠状态）；菜单项固定高度 48px；支持二级菜单
- 主内容区：`flex: 1`，`min-width: 1024px`，内部 padding 20px，背景 #F5F7FA
- 主内容区必须 `overflow: auto`，超宽表格横向滚动，不撑破布局
- 主内容区顶部固定 PageHeader 区（页面标题 + 操作按钮），下方内容滚动

## 各页布局规则
- 列表页：顶部筛选条（一行内排列，超出时折行）+ 工具栏（新增/导出/批量操作）+ 表格 + 分页；表格 `min-width` 按列数设定，超出主区横向滚动
- 表单页：单列或双列栅格（Element Plus `el-row/el-col` 固定 span，不做响应式），表单最大宽度 960px 居中
- 详情页：顶部摘要卡 + 下方标签页切换（基本信息 / 配血记录 / 发血记录 / 不良反应 / 操作日志）
- 配血工作台：固定左右分栏（左 380px + 右自适应），**不折叠不响应式**，主内容区 <1280px 时右侧列表内部横向滚动
- 仪表盘：三行栅格（4 卡 / 2:1 图表 / 待办列表），固定列宽用 flex 比例，不写响应式断点
- 冰箱视图：冰箱卡片横向 flex 排列（每个 min-width 240px），血袋网格用 CSS Grid（`grid-template-columns: repeat(auto-fill, 56px)`）
- 追溯时间轴：单列居中，最大宽度 900px
- 弹窗：宽度 480 / 640 / 800 三档，居中，内容超出高度时内部滚动，不撑出视口

## 滚动条与溢出
- 统一自定义滚动条样式（宽 8px，浅灰圆角，hover 加深），全站生效
- 表格 `el-table` 必须设置 `height` 或 `max-height`，让表头固定、内容区滚动
- 长文本（诊断、备注）：列表内 `line-clamp: 2 + ellipsis`，详情内完整显示

## 打印页

# 交互反馈规范（业务页面强制，登录页除外）

## 统一时长与缓动
- 全部过渡使用 150ms（hover/focus）或 80ms（active 按下）
- 缓动统一 ease-out，禁止 bounce / elastic / spring
- 页面切换 200ms fade-slide，弹窗 200ms scale+fade
- 禁止任何 >400ms 的装饰性动画（状态脉冲除外）

## 必须实现的反馈（缺一不可）
1. 所有按钮：hover 背景加深一档 / active scale(0.97) / disabled 透明度 0.5 + cursor: not-allowed
2. 表格行：hover 背景 #F5F7FA（120ms）
3. 可点击行：hover 时行首出现 2px 主色条 或 文字变主色 + cursor: pointer
4. 输入框：focus 时 1px 主色描边 + 2px 外发光 ring（box-shadow: 0 0 0 3px rgba(37,99,235,.12)）
5. 侧边栏菜单：hover 左侧 3px 主色条 transform: scaleY(0→1) 滑入
6. 血袋列表选中行：主色描边 + #EFF6FF 底色；未选中 hover 时浅灰底
7. 排序/折叠图标：点击旋转 180°（200ms）
8. 写操作按钮（入库/配血/发血/报废/上报不良反应）：提交中 spinner + disabled；成功后 1.5s 绿色打勾反馈
9. 铃铛新预警：图标 rotate 摇摆一次（keyframes 400ms）+ 红点数字 scale 弹跳（1→1.2→1，200ms）
10. 表单校验失败：对应输入框红色描边 + 轻微左右抖动（keyframes 300ms，仅一次）
11. 冰箱网格色块：hover 上浮 1px + 描边加深；点击选中态主色描边
12. 追溯时间轴节点：hover 背景变浅灰，可点击节点显示 pointer

## 明确禁止
- 卡片/按钮 hover 位移超过 2px
- 无限循环装饰动画（状态脉冲、紧急 Tag 除外）
- hover 才显示的关键业务信息（血型、效期、相容性结论必须常驻可见）
- 大于 400ms 的过渡
- 任何 spring/bounce 缓动

## 可访问性
- 所有交互必须有键盘可达路径（Tab 聚焦 + Enter 触发）
- focus 状态可见（外发光 ring），不能只依赖 hover
- 动画遵循 prefers-reduced-motion：媒体查询内将 transition 时长设为 0.01ms
