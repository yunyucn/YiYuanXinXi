# 输血管理系统验收操作手册

## 1. 最快演示：一条命令

在项目根目录打开 PowerShell，只执行：

```powershell
python backend/acceptance_check.py
```

不需要新建虚拟环境，不需要开第二个终端，不需要手工建数据库，也不需要提前启动前后端。

脚本会自动完成：

1. 运行 pytest。
2. 创建临时 SQLite 数据库。
3. 启动临时后端。
4. 执行完整 HTTP 主流程。
5. 关闭后端并删除临时数据。

成功时重点看到：

```text
8 passed
ACCEPTANCE PASSED
VERIFY PASSED
```

其中 E2E 会打印入库储血号、申请单号、发血记录号、发血审计证据，以及医生和护士访问系统管理接口的 `HTTP 403`。

> 当前电脑的依赖已经安装。只有换电脑或重装 Python 后，才需要执行一次：
>
> `python -m pip install -r backend/requirements.txt`

## 2. 界面业务演示

界面演示与上面的自动验收相互独立。测试命令已经包含真实业务主流程，老师要求看页面时再启动前后端。

如果本机保留了原来的 `start.bat`，直接双击即可。也可以手工启动：

```powershell
cd backend
python app.py
```

另开一个终端：

```powershell
cd frontend
npm run dev
```

访问 `http://127.0.0.1:5173`，账号密码均为 `123456`。

## 3. 页面演示顺序

| 顺序 | 使用账号 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 1 | `doctor` | 提交一例 A 型 Rh 阳性、2U 悬浮红细胞申请 | 申请状态为“待配血” |
| 2 | `tech` | 在配血工作台先尝试 B 型血袋，再选择相容的 A 型血袋 | 错误血袋被拦截，正确血袋完成配血，状态为“备血锁定” |
| 3 | `tech` | 在发血工作台完成四项核对并发血 | 生成发血记录，护士端出现“待执行” |
| 4 | `nurse` | 确认输血执行 | 执行状态为“已完成” |
| 5 | `nurse` | 上报一条轻度发热不良反应 | 追溯时间轴出现不良反应事件 |
| 6 | `admin` | 在操作日志搜索“发血” | 查到 `完成发血` 和刚才的发血记录号 |

验收任务中的“发药”在本系统对应“发血”；系统没有收费员角色，越权测试使用 `doctor` 或 `nurse` 访问 `/api/system/*`。

## 4. 现场讲解要点

- 先运行一条命令，展示 `8 passed`、`ACCEPTANCE PASSED`、`VERIFY PASSED`。
- 说明 E2E 不是查数据库，而是真实发起 HTTP 请求，角色依次为医生、技师、护士、管理员。
- 指出 E2E 输出的审计证据和 `HTTP 403`，分别对应审计日志与越权验收项。
- 页面演示时重点展示一次“不相容配血被后端拦截”。
- 未实现项按 `docs/验收说明.md` 如实说明，不声称自备血全流程、费用管理或 HIS/LIS 接口已完成。

## 5. 关闭

- 自动验收脚本运行结束后会自行退出并清理临时数据。
- 页面演示结束后，在前后端终端按 `Ctrl + C`；如果使用 `start.bat`，运行原来的 `stop.bat`。
