# 输血管理系统验收操作手册

## 1. 演示原则

- 全部操作现场完成，不使用提前录制的视频。
- 演示数据可以预置，但每一次申请、配血、发血、执行和上报都必须真实提交到后端。
- 先展示 pytest 和 E2E 证据，再展示界面业务链；测试与业务演示互不替代。

## 2. 启动前准备

在项目根目录打开 PowerShell。

后端首次准备：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python init_db.py
```

前端首次准备：

```powershell
cd frontend
npm install
```

日常启动使用两个 PowerShell 窗口：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python app.py
```

```powershell
cd frontend
npm run dev
```

打开 `http://127.0.0.1:5173`，推荐浏览器窗口为 1440×900。所有账号密码均为 `123456`。

## 3. 自动化测试现场执行

### 3.1 pytest

在第一个终端停止后端，或新开终端进入后端目录：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m pytest -q
```

预期结果：

```text
7 passed
```

覆盖内容包括登录鉴权、管理员接口越权、ABO/Rh 相容性、入库复检、配血、发血、执行、不良反应、追溯、预警和报表权限，并断言发血操作已写入审计日志。

### 3.2 HTTP E2E

E2E 需要一个运行中的后端。为避免影响日常演示数据，建议使用独立验收库。

终端 A：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
$env:DATABASE_URL = "sqlite:///./data/e2e_acceptance.db"
$env:SCHEDULER_ENABLED = "0"
python init_db.py
python app.py
```

终端 B：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python tests/e2e_api.py --base-url http://127.0.0.1:5000/api
```

预期末尾输出：

```text
ACCEPTANCE PASSED
```

E2E 会真实完成入库、申请、待办发现、配血锁定、四项核对发血、护士执行、不良反应、追溯、审计查询和越权校验。成功后会打印申请单号、发血记录号和住院号。

验收结束后在终端 A 按 `Ctrl + C` 停止后端，并清理当前终端的环境变量：

```powershell
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:SCHEDULER_ENABLED -ErrorAction SilentlyContinue
```

`backend/data/e2e_acceptance.db` 已在 Git 忽略范围内，不会提交。

## 4. 八至十二分钟现场业务演示

### 第 1 步：医生提交申请

1. 使用 `doctor / 123456` 登录。
2. 进入“输血申请”，填写患者姓名、住院号、科室、血型 A、Rh D阳性、品种“悬浮红细胞”、数量 2U。
3. 提交后确认申请状态为“待配血”。

讲解要点：申请单由医生账号创建，状态不是前端写死，而是后端写入并可被技师待办读取。

### 第 2 步：技师演示不相容拦截

1. 切换 `tech / 123456`，进入“配血工作台”。
2. 找到刚创建的申请单。
3. 先选择 B 型红细胞尝试配血，确认系统提示不相容并拦截。
4. 再选择 A 型 Rh 阳性、有效期更近的推荐血袋完成配血。

预期变化：申请状态变为“已备血”，血袋状态变为“备血锁定”。

讲解要点：FEFO 会优先推荐近效期血袋；最终提交由后端再次做 ABO/Rh 校验，不能绕过界面直接提交错误配血。

### 第 3 步：技师四项核对并发血

1. 进入“发血工作台”。
2. 确认申请单、血袋、有效期和配血结论四项核对。
3. 输入领血护士并提交。

预期变化：生成发血记录号，申请和血袋状态变为“已发血”，护士端出现“待执行”记录。

### 第 4 步：护士执行确认

1. 切换 `nurse / 123456`。
2. 打开待执行发血记录，确认领血和输血执行。

预期变化：执行状态变为“已完成”，系统记录执行护士和执行时间。

### 第 5 步：护士上报不良反应

1. 在已完成记录上新增不良反应。
2. 选择反应类型“发热”、程度“轻度”，填写处理措施并提交。

预期变化：不良反应列表新增记录，追溯时间轴出现警告事件。

### 第 6 步：追溯与审计

1. 使用住院号打开“全周期追溯”，确认申请、配血、发血、执行、不良反应五类事件齐全。
2. 切换 `admin / 123456`，进入“系统管理 → 操作日志”。
3. 关键字输入“发血”，找到刚才的发血记录。

审计证据应包含：

- 操作：`完成发血`
- 目标类型：`发血记录`
- 目标编号：刚才的发血记录号
- 详情：申请单号与领血护士

验收任务中的“发药”在本系统对应“发血”，现场以此关键字查询。

### 第 7 步：越权 403 演示

可在 PowerShell 现场验证，不需要修改前端：

```powershell
$body = '{"username":"doctor","password":"123456"}'
$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/api/auth/login -ContentType 'application/json' -Body $body
$headers = @{ Authorization = "Bearer $($login.data.access_token)" }
try {
    Invoke-RestMethod -Uri http://127.0.0.1:5000/api/system/logs -Headers $headers
} catch {
    "HTTP " + [int]$_.Exception.Response.StatusCode
}
```

预期输出：

```text
HTTP 403
```

将用户名换成 `nurse` 同样为 403；换成 `admin` 才能读取系统日志。

## 5. 演示收尾

1. 在前后端终端分别按 `Ctrl + C`。
2. 确认没有遗留测试数据库进入 Git：`git status --short` 不应出现 `.db` 或 `.bat`。
3. 答辩时按“提示词拆分 → AI 生成 → 人工审查与修改 → 自动化测试 → Git 提交”说明协作过程。
