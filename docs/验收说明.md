# 输血管理系统验收说明

## 1. 验收定位

本系统面向医院输血科与临床用血场景，实现了从血液入库、临床申请、相容性配血、发血核对、护士执行、不良反应上报到全周期追溯的业务闭环。验收以真实操作和可重复执行的自动化测试为准，不使用录屏替代现场流程，也不在前端页面堆砌“模块已完成”等验收文案。

## 2. 验收环境

| 项目 | 基线 |
| --- | --- |
| 操作系统 | Windows 10 / 11 |
| 后端 | Python 3.10+、Flask、SQLite |
| 前端 | Node.js 18+、Vue 3、Vite、Element Plus |
| 推荐分辨率 | 1440×900，兼容 1280×720 |
| 部署方式 | 本地离线部署，不依赖外部云服务或在线字体 |
| 自动化测试 | `pytest 8.3.4`、Python 标准库 HTTP E2E |

## 3. 角色与接口映射

演示场景中常见的“收费员访问 `/admin/*`”，可按以下关系映射到本系统：

| 常见表述 | 本系统对应 | 说明 |
| --- | --- | --- |
| 收费员 | `doctor` 或 `nurse` | 系统未设置收费业务，使用普通业务角色验证越权行为 |
| `/admin/*` | `/api/system/*` | 用户、日志、字典和冰箱维护等系统管理接口 |
| 发药 | 发血 | 本系统业务对象为血液，审计日志关键字为“发血” |

体验账号密码统一为 `123456`：

| 用户名 | 角色 | 主要职责 |
| --- | --- | --- |
| `admin` | 血库管理员 | 系统管理、用户与操作日志 |
| `tech` | 输血科技师 | 入库、配血、发血、报废申请 |
| `doctor` | 临床医生 | 提交输血申请、查看申请状态 |
| `nurse` | 护士 | 领血执行、不良反应上报 |
| `director` | 科室主任 | 报废审批、统计报表 |

## 4. 功能点逐项核验

| 功能点 | 状态 | 实现与证据 | 现场核验方式 |
| --- | --- | --- | --- |
| 入库管理 | 已实现 | `backend/routes/blood_bag.py` 支持单袋与批量入库，自动生成储血号；品种字典决定有效期；七项复检必须完整；不合格血液自动生成待审批报废记录 | 技师进入入库页，提交一袋 A 型 Rh 阳性悬浮红细胞，观察库存和效期 |
| 配血管理 | 已实现 | `backend/routes/cross_match.py`、`backend/utils/compatibility.py` 实现 ABO/Rh 相容性矩阵、FEFO 推荐、数量校验和不相容拦截；配血成功后血袋锁定 | 医生提交申请，技师选择不相容血袋应先被拦截，再选择相容血袋完成备血 |
| 发血管理 | 已实现 | `backend/routes/issue.py` 校验申请状态、血袋锁定、有效性和有效配血记录；四项核对齐全后生成发血记录号并写入审计日志 | 技师完成四项核对后发血，护士端应出现待执行记录 |
| 报废管理 | 已实现 | `backend/routes/scrap.py` 支持技师申请或过期批量申请，主任批准/驳回；批准后血袋置为已报废并记录经手人、审批人、原因和日期 | 发起报废申请，切换到主任账号完成审批 |
| 自备血管理 | 部分实现 | 入库模型和页面提供 `is_autologous` 标识，库存中可识别自备血属性；未提供独立的“自备血发血、自备血查询、自备血袋签”专项工作流 | 入库时可勾选自备血；说明当前为属性级支持，不冒充完整专项模块 |
| 有效期管理 | 已实现 | `backend/models.py` 提供效期与临期等级；`backend/utils/alerts.py` 定时扫描临期、过期和低库存；预警中心支持处理和去重 | 查看库存效期倒计时、预警中心和手动扫描结果 |
| 费用管理 | 未实现 | 本期未建立费用流水，也未伪造住院处自动计费。真实计费需要与 HIS/住院收费系统约定接口、对账和退费规则 | 说明属于系统外部集成范围，避免以静态金额冒充真实计费 |
| 查询与统计 | 已实现主要业务统计 | 支持入出库趋势、当前库存、血型库存、科室用血、报废数和不良反应分布；报表可导出 CSV；费用查询未实现 | 主任账号选择日期范围查看报表并导出 CSV |
| 实时读取其他系统 | 未实现 | 当前为离线本地部署，没有 HIS/LIS 实时接口。系统内部数据由入库、申请、配血、发血、执行和不良反应流程实时联动 | 说明这是部署边界，不伪造外部系统连接 |
| 运行速度与易用性 | 已实现并通过现场验证 | 本地 SQLite 响应快；菜单按角色呈现；表单校验、状态色、路由加载骨架、统一操作列和响应式表格降低误操作 | 现场完成一条业务链并观察状态流转与提示 |

## 5. 验收对照

| 验收要求 | 证据 |
| --- | --- |
| 演示真实操作，不播放录屏 | `docs/验收操作手册.md` 给出页面操作顺序，所有状态由真实接口变更 |
| 逐项核验功能点 | 本文第 4 节逐项列出已实现、部分实现和未实现内容 |

| pytest 与 E2E 现场跑通 | 在项目根目录执行 `python backend/acceptance_check.py`，本次实测输出 `8 passed`、`ACCEPTANCE PASSED`、`VERIFY PASSED` |
| 审计日志可查“发药”操作 | 本系统对应“发血”；管理员按关键字“发血”查询，日志包含 `完成发血`、发血记录号和申请单号 |
| 开发过程与人工审查说明 | 见 `docs/开发过程说明.md` |
| 智能辅助功能 | FEFO 血袋推荐、临期/低库存/超时预警属于离线、可解释的规则型智能辅助，不调用外部大模型 |

## 6. 明确的系统边界

- 自备血目前提供入库属性标识，不声称已完成独立的自备血全流程。
- 费用管理与住院处自动计费未实现，不在前端制造虚假账单。
- 外部 HIS/LIS 实时读取未实现，当前依赖本地业务数据闭环。
- 系统用于课程设计、管理软件实践和业务演练，不替代医院正式信息系统或临床决策。
