# 输血管理分系统

面向课程设计与课堂演示的单机版医院输血管理分系统，覆盖「血液入库 → 库存与效期管理 → 临床输血申请 → ABO/Rh 配血 → 发血 → 护士执行 → 不良反应上报 → 全周期追溯 → 报废 → 统计」完整闭环。

系统仅适配 PC 桌面端，前端业务页采用扁平化设计、1px 描边和克制的状态色；登录页使用玻璃拟态与渐变作为独立视觉入口。全部依赖本地安装，不使用 CDN、在线字体或云服务。

界面统一使用医疗蓝渐变、页面标题强调条、统计卡浅渐变与 Element Plus 组件图标；页面标题和统计卡叠加低透明度内联 SVG 纹理，关键操作按钮使用渐变强调与悬停扫光效果。表格操作列由 `TableActions` 统一渲染，最多三个操作保持单行，避免不同分辨率下按钮换行。业务路由采用懒加载 + `RouteLoading` 骨架 + 路由错误兜底，切换页面时不会出现整页白屏。

## 技术栈

- 后端：Python 3.10+、Flask、Flask-CORS、Flask-SQLAlchemy、Flask-JWT-Extended、APScheduler
- 数据库：SQLite，默认文件 `backend/data/bloodbank.db`
- 前端：Vue 3（Composition API + `<script setup>`）、Vite、Vue Router、Pinia、Axios
- UI：Element Plus（按需引入）、SCSS 主题变量、ECharts
- 打印：浏览器 `window.print()` + 专用打印样式，包含 A4 输血记录单和血袋标签


`python init_db.py` 会重建表并灌入演示数据，重复执行会清空当前数据库。应用启动时 APScheduler 会立即执行一次预警扫描，之后每 10 分钟扫描一次。

### 2. 前端

```powershell
cd E:\医院信息系统\YiYuanXinXi\frontend
npm install
npm run dev
```

访问：`http://127.0.0.1:5173`

```powershell

```

- 双击项目根目录的 `start.bat`：分别打开后端与前端命令行窗口，并自动打开浏览器。
- 双击项目根目录的 `stop.bat`：关闭占用 `5000`、`5173` 端口的后端和前端服务。
- 手动关闭：切换到运行 `python app.py` 或 `npm run dev` 的窗口，按 `Ctrl + C`，再关闭窗口即可。

## 功能清单

### 血液管理

- 单袋入库与批量入库，储血号按 `XZ + 日期 + 序号` 自动生成。
- 有效期按品种字典保质期自动计算：全血/悬浮红细胞 35 天、血浆 365 天、血小板 5 天、冷沉淀 365 天。
- 入库必须选择正常状态冰箱，并录入定血型、Rh、ALT、HIV、梅毒、乙肝、丙肝 7 项复检结果。
- 复检不完整禁止入库；复检不合格不入库，自动生成待审批报废记录。
- 库存列表显示效期倒计时、临期/过期行高亮，支持筛选、详情、袋签打印和批量报废。
- 冰箱视图按物理位置展示在库、备血锁定、已过期血袋；已发血、已报废血袋不显示。色块 hover 显示 tooltip，点击打开详情抽屉。

### 输血闭环

- 医生提交输血申请，支持常规、紧急、抢救三档紧急程度。
- 配血工作台展示待配血队列、等待时长和推荐血袋。
- 配血前执行 ABO/Rh 相容性校验；不相容血袋在表格中标红且不可选择，绕过前端提交也会被后端 400 拦截并记录。
- 配血成功后血袋变为「备血锁定」，申请单变为「已备血」；取消配血会解锁血袋。
- 发血前必须完成申请单、外观、效期、配血结果四项核对，并填写领血护士。
- 发血后血袋变为「已发血」，申请单同步变为「已发血」。
- 护士确认执行后申请单变为「已完成」，执行人和执行时间进入追溯链路。
- 已完成记录可上报发热、过敏、溶血或其他不良反应，支持轻/中/重度、处理措施和是否上报血站。

### 预警、追溯与报表

- 预警类型：临期、过期、低库存、待配血超时、复检未完成。
- 预警中心显示上次/下次扫描时间、扫描日志、手动扫描结果与处理记录。
- 铃铛红点只统计未处理的「警告 + 严重」预警，提示级不计入。
- 立即扫描会将今天及以前到期的在库血袋自动改为「已过期」，并去重生成预警。
- 全周期追溯按住院号串联申请、配血、发血、执行和不良反应；不相容配血节点红色，不良反应节点橙色。
- 统计报表包含出入库趋势、血型库存、科室用血、不良反应分布和每日明细，支持 CSV 导出。

### 系统管理

- 用户管理：新增用户、编辑资料、启用/停用、重置密码。
- 科室管理：新增临床科室并关联用户。
- 品种字典：维护分类、保质期、安全库存、单位和说明。
- 冰箱管理：维护编号、位置、容量与正常/维护状态。
- 操作日志：记录入库、配血、发血、执行、预警处理、报废审批等关键动作。

## 核心业务规则

### ABO/Rh 相容性

- 红细胞受者：A 接受 A/O，B 接受 B/O，AB 接受 A/B/AB/O，O 只接受 O。
- 血浆/冷沉淀受者：A 接受 A/AB，B 接受 B/AB，AB 只接受 AB，O 接受 A/B/AB/O。
- Rh 阴性受者不得接受 Rh 阳性红细胞、血浆或血小板。
- Rh 阳性受者接受 Rh 阴性血液时返回提示级相容，允许输注但要求记录。
- 血小板 ABO 不同型返回提示级；Rh 阴性受者接受 Rh 阳性血小板直接拦截。

### 状态联动

- 配血成功：血袋 `在库 → 备血锁定`，申请单 `待配血/配血中 → 已备血`。
- 取消配血：血袋 `备血锁定 → 在库`，申请单 `→ 待配血`。
- 完成发血：血袋 `备血锁定 → 已发血`，申请单 `已备血 → 已发血`。
- 确认执行：申请单 `已发血 → 已完成`，发血记录 `待执行 → 已完成`。
- 批准报废：血袋 `→ 已报废`；驳回后血袋状态保持不变。
- 扫描到期：在库血袋 `→ 已过期`，并写入扫描日志与预警。

## 课堂演示脚本（10–12 分钟）

1. **登录（30s）**：切换 `admin / tech / doctor / nurse / director`，观察左侧菜单差异。
2. **仪表盘（1min）**：查看在库、待配血、临期、今日发血统计卡，以及趋势、血型占比和预警待办。
3. **血液入库（1min）**：录入一袋悬浮红细胞，观察储血号与有效期自动计算；故意留空复检项被拦截，再演示复检不合格生成报废申请。
4. **库存冰箱视图（1min）**：切换冰箱 Tab，打开有临期血的冰箱，观察色块、tooltip 和详情抽屉。
5. **配血工作台（2min）**：选择 A 型患者申请，B 型血袋标红不可选；改选 A/O 型血袋提交，血袋锁定、申请单转为已备血。
6. **预警中心（1.5min）**：点击「立即扫描」，观察新增预警与自动过期数量；铃铛红点弹跳，扫描日志出现手动记录。
7. **发血与打印（1min）**：完成四项核对并填写领血护士，发血后打开输血记录单打印预览。
8. **护士执行与不良反应（1min）**：护士确认执行，随后上报一条不良反应。
9. **全周期追溯（1min）**：输入 `ZY20240512005`，展示申请、配血、发血、执行、不良反应时间轴。
10. **统计报表（30s）**：查看图表与每日明细，导出 CSV。
11. **报废审批（30s）**：使用主任账号批准一条待审批报废记录，观察血袋状态变为已报废。
12. **权限与日志（30s）**：使用医生账号尝试访问系统管理或入库接口，验证 403；管理员查看操作日志。

## 常见问题

- **端口被占用**：后端默认 `5000`，前端默认 `5173`；关闭占用进程或修改 `app.py` / `vite.config.js`。
- **登录 401**：确认后端已启动，且数据库已执行 `python init_db.py`。
- **重置演示数据**：停止后端后重新执行 `python init_db.py`，再启动 `python app.py`。
- **打印样式**：记录单按 A4 预览，袋签为 100mm × 70mm 标签；浏览器打印时请关闭页眉页脚并启用背景图形。
- **暗色模式**：右上角月亮/太阳按钮切换，主题保存在浏览器 localStorage。

## Git 提交规范

建议使用 Conventional Commits，按模块分批提交，例如：

```text
feat(backend): 实现血液入库与复检校验
feat(cross-match): 增加 ABO/Rh 相容性拦截
feat(alert): 接入启动扫描与预警去重
feat(frontend): 搭建主框架与角色菜单
feat(report): 增加统计图表与 CSV 导出
fix(alert): 修正提示级预警计入红点的问题
docs(readme): 补充启动说明与课堂演示脚本
```

提交前确认不包含 `data/*.db`、`node_modules`、`dist`、`.venv`、`__pycache__` 或密钥文件。当前工作区未自动创建 Git 提交，便于审阅后按模块整理提交历史。
